Descriptive Statistics: From Raw Data to Publication-Ready Output

A demonstration of live reproducible analysis in R — rendered code, formatted tables, and embedded figures that cannot be replicated accessibly within Canvas.
NoteAbout this page

Every table and figure here is produced by the R code shown — not a screenshot, not a pasted image. Students can read the code, copy it, modify it, and run it themselves.

Canvas cannot replicate this. Canvas Pages support uploaded image files and a basic HTML table editor, but have no ability to render live code alongside its output, produce accessible formatted statistical tables, or embed reproducible figures that update automatically when the underlying data changes.

The Scenario

You have received a dataset of county-level characteristics for 15 North Carolina counties. The data are messy: one value is missing and you need to derive a new categorical variable before producing summary statistics. Your task is to:

  1. Inspect and clean the data
  2. Produce a formatted descriptive statistics table broken down by region
  3. Visualize the relationship between median household income and per capita public expenditure

Step 1 — Load and Inspect

library(tidyverse)
library(gt)
library(scales)

# Simulated NC county data (representative values, not official statistics)
counties_raw <- tibble(
  county     = c("Wake", "Mecklenburg", "Guilford", "Forsyth", "Durham",
                 "Buncombe", "New Hanover", "Cumberland", "Gaston", "Onslow",
                 "Cabarrus", "Union", "Catawba", "Pitt", "Alamance"),
  region     = c("Piedmont", "Piedmont", "Piedmont", "Piedmont", "Piedmont",
                 "Mountains", "Coastal", "Coastal", "Piedmont", "Coastal",
                 "Piedmont", "Piedmont", "Piedmont", "Coastal", "Piedmont"),
  population = c(1129410, 1115482, 541299, 382295, 330506,
                 275203, 234473, 335509, 228928, 207647,
                 218000, 245318, 159551, 177372, 169509),
  med_income = c(78500, 72100, 56300, 54200, 65800,
                 NA, 61400, 49300, 55200, 52100,
                 67300, 79200, 55600, 48700, 54100),
  unemp_rate = c(3.1, 3.4, 4.2, 4.5, 3.8,
                 3.9, 4.1, 5.2, 4.8, 6.1,
                 3.7, 3.2, 4.4, 5.0, 4.6),
  expend_pc  = c(3842, 4120, 3256, 3189, 4567,
                 2987, 3421, 2876, 2654, 2543,
                 3102, 3456, 2876, 2987, 2765)
)

Notice that med_income for Buncombe County is NA. We handle this in the next step.

Step 2 — Clean the Data

The code below performs three operations. Hover over the numbered annotations to see what each does.

counties <- counties_raw |>
  mutate(
1    med_income = if_else(
      is.na(med_income),
      median(med_income, na.rm = TRUE),
      med_income
    ),
2    income_group = case_when(
      med_income >= 70000 ~ "High",
      med_income >= 55000 ~ "Middle",
      .default            = "Lower-Middle"
    ),
3    income_group = factor(
      income_group,
      levels = c("Lower-Middle", "Middle", "High")
    )
  )
1
Impute the missing value. Replaces the single NA in med_income with the column median. In a real analysis, document and justify this decision — median imputation is appropriate when missingness is isolated and the distribution is skewed.
2
Derive a categorical variable. case_when() is cleaner than nested if_else() calls when you have more than two conditions. The .default argument handles any cases not matched above.
3
Set factor level order. Without this step, R sorts categories alphabetically — putting “High” before “Lower-Middle” in tables and figures. Explicit level ordering ensures a logical sequence.

Step 3 — Descriptive Statistics Table

TipWhat Canvas cannot replicate here

The table below has currency-formatted numbers, a spanning column header, a footnote linked to a specific column, and alternating row shading — all generated in a few lines of code. Producing an equivalent in Canvas requires manually entering every value into a basic HTML table editor with no support for number formatting, column groups, or footnotes.

counties |>
  group_by(region) |>
  summarise(
    n          = n(),
    pop_avg    = mean(population),
    income_avg = mean(med_income),
    unemp_avg  = mean(unemp_rate),
    expend_avg = mean(expend_pc),
    .groups    = "drop"
  ) |>
  arrange(region) |>
  gt() |>
  tab_header(
    title    = md("**County Characteristics by Region**"),
    subtitle = "Selected North Carolina Counties (Simulated Data)"
  ) |>
  tab_spanner(
    label   = "Economic Characteristics",
    columns = c(income_avg, unemp_avg, expend_avg)
  ) |>
  cols_label(
    region     = "Region",
    n          = "N",
    pop_avg    = "Avg. Population",
    income_avg = "Median HH Income",
    unemp_avg  = "Unemployment (%)",
    expend_avg = "Expenditure per Capita"
  ) |>
  fmt_integer(columns = pop_avg) |>
  fmt_currency(columns = c(income_avg, expend_avg), decimals = 0) |>
  fmt_number(columns = unemp_avg, decimals = 1) |>
  tab_footnote(
    footnote  = "Income imputed for one county with missing data (median substitution).",
    locations = cells_column_labels(columns = income_avg)
  ) |>
  tab_style(
    style     = cell_fill(color = "#f8fafc"),
    locations = cells_body(rows = c(1, 3))
  ) |>
  tab_style(
    style     = cell_text(weight = "bold"),
    locations = cells_column_spanners()
  ) |>
  tab_options(
    table.width               = pct(100),
    heading.align             = "left",
    column_labels.font.weight = "bold"
  )

Step 4 — Visualization

ggplot(
  counties,
  aes(x = med_income, y = expend_pc, color = region, size = population)
) +
  geom_point(alpha = 0.75) +
  geom_smooth(
    aes(group = 1),
    method   = "lm",
    se       = TRUE,
    color    = "#475569",
    linewidth = 0.6,
    linetype = "dashed"
  ) +
  scale_x_continuous(labels = dollar_format(scale = 1e-3, suffix = "K")) +
  scale_y_continuous(labels = dollar_format()) +
  scale_size_continuous(labels = comma_format(), range = c(3, 10)) +
  scale_color_manual(
    values = c(
      "Coastal"   = "#0ea5e9",
      "Mountains" = "#10b981",
      "Piedmont"  = "#6366f1"
    )
  ) +
  labs(
    title    = "Household Income and Per Capita Expenditure",
    subtitle = "15 Selected North Carolina Counties",
    x        = "Median Household Income",
    y        = "Per Capita Expenditure",
    color    = "Region",
    size     = "Population",
    caption  = "Source: Simulated data for instructional purposes"
  ) +
  theme_minimal(base_size = 13) +
  theme(
    plot.title       = element_text(face = "bold"),
    legend.position  = "right",
    panel.grid.minor = element_blank()
  )

What This Demonstrates

ImportantFive things Canvas cannot do

  1. Rendered code alongside its output. In Canvas, instructors must paste screenshots of code and output as separate images. Students cannot copy, adapt, or verify the code.

  2. Formatted statistical tables. The gt table above has currency formatting, a spanning column header, a footnote linked to a specific column, and conditional row shading. Canvas’s HTML table editor supports none of this.

  3. Code annotations. The hover annotations in Step 2 link explanatory text directly to specific lines of code — a feature impossible in any static platform.

  4. Accessible figure captions and alt text. The fig-cap and fig-alt chunk options produce a proper HTML <figcaption> and alt attribute required for WCAG compliance. Images uploaded to Canvas have no enforced alt text and no semantic caption structure.

  5. Reproducibility. If the underlying data changes, every table and figure on this page updates automatically on the next render. A Canvas page requires manually replacing every screenshot.
